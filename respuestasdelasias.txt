Cómo lo armaría

Una plantilla “config-driven”. El proyecto tiene un archivo site.config.json con todo lo que cambia: nombre, logo, colores, fuentes, teléfono, WhatsApp, dirección, horarios, servicios y textos. Las secciones (hero, servicios, reseñas, galería, contacto) leen de ahí. Así, cambiar de negocio es cambiar el JSON y una carpeta de imágenes, y no hay que tocar HTML.
Tus 3 modelos por rubro salen de combinar layouts y paletas. Con 5 o 6 layouts base y 10 paletas, que son solo variables de color y tipografía, ya tenés cientos de combinaciones sin mantener cientos de proyectos.
Un script para lo mecánico y el agente para lo creativo. Algo como nuevo-sitio.js peluqueria "Nombre" copia la plantilla y deja la carpeta lista. El agente solo completa el JSON, redacta los textos, elige la paleta y corre el build. Se hace en segundos y casi no hay lugar para errores.
Un skill global para tu agente. Un SKILL.md que diga: “cuando te pidan una web, elegí la plantilla según el rubro, copiala, llená el config, hacé build y mostrame el preview”. Como ya trabajás con skills globales, queda disponible desde cualquier carpeta vacía.
Empezar chico. Hacé 1 plantilla perfecta, probala con 3 negocios reales y recién después clonás el patrón. Yo arrancaría por los rubros de los leads que ya tenés, y no por 100 rubros que quizás nunca vendas.

✨ Herramientas únicas y su investigación

Únicas de la Lista 0 (brandonhimpfen)
Esta lista destaca por su enfoque en el rendimiento y el ecosistema TypeScript moderno.

SolidJS: Un framework de UI que, a diferencia de React, no usa un Virtual DOM. Utiliza "reactividad de grano fino" para actualizar solo las partes exactas del DOM que cambian. El resultado es un rendimiento excepcional y un tamaño muy reducido (~7KB).

Astro: Un generador de sitios estáticos "content-first". Su característica principal es que, por defecto, envía cero JavaScript al cliente. Está diseñado para sitios basados en contenido (blogs, documentación) donde la velocidad de carga es crítica, permitiendo "hidratar" componentes interactivos solo cuando es necesario.

Tailwind CSS, Bulma, Material UI, Chakra UI: Librerías de CSS/UI que ofrecen distintos enfoques. Tailwind es "utility-first", Bulma es un framework CSS moderno basado en Flexbox, y Material UI y Chakra UI son librerías de componentes para React.

tRPC: Una herramienta para crear APIs con seguridad de tipos de extremo a extremo en proyectos TypeScript. A diferencia de GraphQL, no requiere un esquema ni generación de código; simplemente compartes los tipos de tu backend con tu frontend. Es más ligero y simple para equipos que ya trabajan con TypeScript.

Prisma: Un ORM (Object-Relational Mapping) moderno para TypeScript y Node.js. Destaca por su seguridad de tipos y su facilidad de uso. Su versión más reciente (v7) ha eliminado la dependencia de Rust, reduciendo drásticamente el tamaño del paquete y mejorando el rendimiento.

FastAPI: Un framework web de alto rendimiento para Python. Está diseñado para construir APIs de forma rápida, con validación de datos automática y documentación interactiva (Swagger UI) incluida por defecto.

Astro, Apollo GraphQL, Sequelize, SQLAlchemy: Otras herramientas notables. Astro ya se mencionó. Apollo es una plataforma completa para GraphQL. Sequelize y SQLAlchemy son ORMs populares para Node.js y Python, respectivamente.

Únicas de la Lista 1 (itsmohitnarayan)
Esta lista brilla por su variedad, incluyendo frameworks ligeros, alternativas históricas y herramientas para nichos específicos.

Alpine.js: Un framework ultraligero (44KB) que se describe como "jQuery para la web moderna". Permite añadir interactividad directamente en tu HTML usando atributos, sin necesidad de un sistema de build complejo. Es perfecto para proyectos sencillos o para mejorar páginas renderizadas en el servidor.

Preact: Una alternativa a React de solo 3KB. Ofrece la misma API y modelo de componentes que React, pero con un tamaño mucho menor y un rendimiento superior en la carga inicial. Es ideal si necesitas la potencia de React pero te preocupa el tamaño del bundle.

Lit: Una librería de Google para construir Web Components (componentes nativos del navegador). Lit proporciona una base sólida para crear componentes rápidos, ligeros y reutilizables en cualquier framework o sin ninguno. Se ha convertido en el estándar de facto para Web Components.

Ember.js: Un framework "convención sobre configuración" para aplicaciones web ambiciosas. Proporciona una estructura muy definida y un conjunto completo de herramientas, lo que lo hace muy productivo para equipos grandes, aunque con una curva de aprendizaje más pronunciada.

Backbone.js: Un framework histórico y minimalista que proporciona estructura a aplicaciones JavaScript mediante modelos, vistas y colecciones. Aunque ya no está en desarrollo activo, su diseño sigue siendo un referente educativo.

Koa: Creado por el equipo detrás de Express, es un framework de Node.js más moderno y minimalista. Utiliza async/await para eliminar el "callback hell", ofreciendo un manejo de errores más limpio. No incluye router por defecto, lo que lo hace más flexible pero también más "crudo" que Express.

Phoenix: Un framework para Elixir, un lenguaje funcional. Destaca por su altísimo rendimiento y su capacidad para manejar tiempo real (WebSockets) de forma nativa y eficiente. Es una excelente opción para aplicaciones con mucha concurrencia, como chats o dashboards en vivo.

Nuxt.js: El framework de referencia para Vue.js. Proporciona una estructura para crear aplicaciones full-stack con renderizado en servidor (SSR) o generación estática (SSG), y un sistema de enrutado y gestión de datos automático.

Eleventy (11ty): Un generador de sitios estáticos simple y flexible. A diferencia de otros, es agnóstico al framework y funciona con múltiples lenguajes de plantillas (Markdown, Liquid, Nunjucks, etc.). Es una alternativa a Jekyll que busca ser más sencilla y rápida.

Hexo: Un framework para blogs, muy popular en el ecosistema Node.js. Está optimizado para la velocidad de generación y es ideal para blogs personales o de documentación que se despliegan en GitHub Pages.

Docusaurus: Un generador de sitios estáticos de Meta (Facebook), especializado en documentación. Construido con React, ofrece una experiencia de usuario muy pulida con navegación rápida, búsqueda y soporte para versionado de documentos.

Sapper y Gridsome: Sapper fue el predecesor de SvelteKit (el framework oficial de Svelte) para SSR. Gridsome es el equivalente a Gatsby pero para Vue.js. Ambos están menos mantenidos hoy en día pero son parte de la historia de sus ecosistemas.

Recursos de CSS y APIs: La lista 1 incluye muchos recursos educativos de CSS (CSS-Tricks, Flexbox Froggy, Grid Garden) y herramientas de gestión de APIs como Postman, Swagger y RapidAPI, que no están en la Lista 0.

📦 La Lista 2 (awesome-selfhosted): Un mundo aparte
Esta lista es fundamentalmente diferente. No comparte ninguna herramienta con las Listas 0 y 1 porque su propósito no es el desarrollo, sino el autoalojamiento.

Qué encontrarás: Aplicaciones completas y listas para usar que puedes instalar en tu propio servidor. Por ejemplo, en la categoría de analíticas encontrarás Umami (una alternativa a Google Analytics). En archivado, ArchiveBox (para crear archivos de sitios web). En blogging, Antville (un software de blogging de alto rendimiento). También hay gestores de documentos, herramientas de sincronización de archivos, clientes de correo, etc.

Solapamiento: Prácticamente nulo. Mientras que las Listas 0 y 1 te dan los materiales y herramientas para construir una casa, la Lista 2 te da casas prefabricadas (y de código abierto) que puedes instalar en tu terreno.

💎 Conclusión
Si buscas el stack moderno y optimizado para un nuevo proyecto (especialmente con TypeScript), la Lista 0 es tu referencia. Destaca por incluir Astro, SolidJS, tRPC y Prisma.

Si buscas variedad, recursos de aprendizaje y quieres conocer alternativas ligeras o históricas (Alpine.js, Preact, Lit, Koa, Phoenix), la Lista 1 es más completa.

La Lista 2 es un recurso complementario y valioso para cuando necesites una aplicación ya hecha (un CMS, un analizador, un gestor de tareas) que puedas ejecutar en tu propio servidor, en lugar de depender de un servicio en la nube.
